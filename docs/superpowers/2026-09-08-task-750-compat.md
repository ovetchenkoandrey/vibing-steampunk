# Задание агенту: совместимость VSP с SAP_BASIS 7.50

Это самостоятельное задание — всё нужное для работы есть в тексте. Работай в форке
`ovetchenkoandrey/vibing-steampunk`, ветка `fix/onprem-752`, локально `C:\Claude\vsp-src`.

## Контекст

VSP (vibing-steampunk) — MCP-сервер для SAP ABAP. Сейчас он отлажен и работает на **COE
(SAP_BASIS 7.52)**. Цель — чтобы он так же работал на **второй системе с SAP_BASIS 7.50**
(тот же класс on-prem NetWeaver, на релиз старше). До 7.50 с этой машины пока не достучаться —
поэтому часть работы оффлайн, часть ждёт доступа. Разделяй эти две части чётко.

Есть три независимых слоя совместимости, не смешивай их:
1. **Язык ABAP** (что компилируется на 7.50) — проверяется оффлайн линтером.
2. **API SAP** (существуют ли на 7.50 используемые стандартные классы/FM: `CL_TPDAPI_SERVICE`,
   `IF_TPDAPI_*`, `CL_APC_WSP_*`, `RSPO_RETURN_ABAP_SPOOLJOB`, `JOB_SUBMIT`, `cl_abap_unit_assert`) —
   только вживую или по документации.
3. **ADT-сервисы** (версии content-type `application/vnd.sap.adt.*.vN+xml`, набор доступных
   REST-ресурсов) — только вживую через `vsp compat`. Именно этот слой дал нам 406 на 7.52.

## Что уже сделано и известно

- **abaplint под `v750` по ядру бэкенда (10 файлов) даёт 0 замечаний** после замены
  `FIND PCRE` → `FIND REGEX` (PCRE появился в 7.55). Это была единственная языковая
  несовместимость; больше ничего из 7.51/7.52 в коде не используется. Способ проверки —
  ниже, повторяй его после любой правки ABAP.
- На COE 7.52 уже применены и задеплоены в `$ZVSP` правки, которые с высокой вероятностью
  нужны и на 7.50: PCRE→REGEX; явный `FIELD-SYMBOLS <fs_tab> TYPE ANY TABLE` в
  `ZCL_VSP_RFC_SERVICE` (inline-декларация в generic-контексте не компилируется);
  из `ZCL_VSP_APC_HANDLER` убран `APPEND zcl_vsp_git_service` (без abapGit не собирается);
  переписан `ZCL_VSP_REPORT_SERVICE` (JOB_SUBMIT + хелпер `ZVSP_SPOOL_XPRT` + INDX — в APC
  запрещены SUBMIT/DESTINATION/спул); в `ZCL_VSP_DEBUG_SERVICE.ensure_bp_context` добавлен
  `i_ide_id = 'VSP'` (с пустым ide_id внешние точки не срабатывают).
- Go-сторона: `pkg/adt/transport.go` — Accept-fallback `transportorganizer.v1;q=0.9` для
  `ListTransports` (406 на tree-only Accept). На 7.50 таких мест может быть больше.

## Как проверять язык оффлайн (повторяемо)

```
mkdir lint750 && cd lint750 && mkdir src
# скопировать в src/ ядро: zif_vsp_service.intf.abap zcl_vsp_utils.clas.abap
#   zadt_cl_tadir_move.clas.abap zcl_vsp_rfc_service.clas.abap zcl_vsp_debug_service.clas.abap
#   zcl_vsp_amdp_service.clas.abap zcl_vsp_report_service.clas.abap zcl_vsp_apc_handler.clas.abap
#   zvsp_spool_xprt.prog.abap zcl_adt_00_amdp_test.clas.abap  (из embedded/abap)
cat > abaplint.json <<'EOF'
{ "global": { "files": "/src/**/*.abap" },
  "syntax": { "version": "v750", "errorNamespace": "^(Z|Y|LCL_|TY_|LIF_)" },
  "rules": { "parser_error": true } }
EOF
npx --yes @abaplint/cli
```
Ожидаемо: `0 issue(s)`. Любая строка `Statement does not exist in the configured ABAP version` —
языковая несовместимость с 7.50, чинить в `embedded/abap/*` и перепроверять.

## Задачи

### A. Оффлайн (можно прямо сейчас)
1. Убедиться, что `embedded/abap` 7.50-чистый линтером (выше). Если что-то всплывёт — править.
2. Пройти Go-сторону на ADT-версионность: `grep -rn "vnd.sap.adt" pkg/adt/` — выписать все
   Accept/Content-Type с версиями (`.v1`, `.v2`, `tree.v1` и т.п.). Каждый — кандидат на 406 на
   7.50. Не менять вслепую: составить список «эндпоинт → какие версии шлём → есть ли fallback».
   Fallback по образцу 406-фикса добавлять только после подтверждения на живой 7.50.
3. Записать выводы в `docs/superpowers/capability-map.md` (колонки `answer`/`cause` для 7.50).

### B. Когда 7.50 доступна (сначала — только чтение!)
1. Подключение: отдельный профиль в `~/.vsp.json` (системы `dev` = COE, добавить вторую),
   пароль ТОЛЬКО через env `VSP_<SYSTEM>_PASSWORD` / `SAP_PASSWORD`, не хардкодить, не коммитить.
2. `vsp -s <750> compat` — что система поддерживает по ADT; сохранить вывод в
   `docs/superpowers/sweeps/compat-750.txt`. Сравнить с COE: расхождения = где ждать 406/404.
3. `vsp -s <750> sweep --json > docs/superpowers/sweeps/sweep-750.json` — карта чтений
   (свип автора никогда не пишет, это безопасно).
4. Только после этого — деплой бэкенда ZADT_VSP на 7.50 **вручную**, НЕ через
   `install_zadt_vsp` (установщик не проверяет `result.Success` и рапортует Deployed при провале):
   создать локальный пакет; порядок объектов: ZIF_VSP_SERVICE → ZCL_VSP_UTILS →
   ZADT_CL_TADIR_MOVE → ZCL_VSP_RFC_SERVICE → ZCL_VSP_DEBUG_SERVICE → ZCL_ADT_00_AMDP_TEST →
   ZCL_VSP_AMDP_SERVICE → ZCL_VSP_REPORT_SERVICE → ZVSP_SPOOL_XPRT → ZCL_VSP_APC_HANDLER;
   деплоить через `SAP(action="edit", target="CLAS X", params={"source":..., "package": "$PKG"})`
   (именно `package`; у `create` параметр называется `package_name` — не перепутать);
   после КАЖДОГО объекта — оракул: `SELECT ... FROM TADIR WHERE DEVCLASS='$PKG'` и отсутствие
   в `DWINACTIV`. Затем руками в GUI: SAPC (приложение ZADT_VSP, handler ZCL_VSP_APC_HANDLER,
   stateful) и SICF (`/sap/bc/apc/sap/zadt_vsp` активен).
5. Смоук после деплоя: `SAP(action="info")`, `search`, `read`, SQL по `T000`,
   `system list_transports`, `debug RUN_REPORT` на тестовом отчёте, `rfc` / `debug CALL_RFC`
   с `RFC_SYSTEM_INFO`. Каждый результат — сверять оракулом, не верить «success» на слово.

### C. Правила (жёсткие)
- Пишем только в песочницу: пакет `$ZVSPTEST`, объекты с префиксом `ZVT_`. Вне её — ничего.
- **`release_transport` не делать никогда** (необратимо). `create_transport` → проверить → `delete_transport` — можно.
- Никогда не доверять ответу тула «success» без независимой проверки (TADIR/TDEVC/DWINACTIV/E070/чтение исходника).
- Секреты (пароли, внутренние адреса) — не в коммиты, не в документы репы.
- Правки — в форк, ветка `fix/onprem-752` (или новая `fix/onprem-750`), коммиты по смыслу.

### D. Известные грабли (чтобы не переоткрывать)
- ADT 406 на tree-only Accept (транспорты) — есть fallback в Go; на 7.50 проверить остальные.
- `install_zadt_vsp` врёт об успехе; «зомби»-пакет (ADT: exists, TDEVC: нет) — брать другое имя.
- `create` поверх существующего объекта может его снести (cleanup при ошибке).
- В APC push channel запрещены операторы с неявным DB-коммитом: SUBMIT (любой), CALL FUNCTION DESTINATION, чтение спула → RABAX; vsp прячет это за «timeout».
- Дебаг: точки срабатывают только в сессиях внутри scope листенера (RFC/submit-цепочка), НЕ в чужой GUI-сессии; фоновые джобы не honor точки на коде отчёта. `DELETE_BREAKPOINT` по id не работает; чистка всех точек — отчёт `ZVSP_BP_CLEAR`.
- MCP `action=debug` ходит через RFC-gateway (порт 33xx), который часто рвётся («rfc: closed»); надёжнее прямой WebSocket к `/sap/bc/apc/sap/zadt_vsp`.
